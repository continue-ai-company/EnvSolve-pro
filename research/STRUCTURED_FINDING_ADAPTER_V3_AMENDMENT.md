# Structured Finding Adapter v3 Amendment

Status: development-informed recorded-case amendment; no new benchmark execution.

The first read-only collector qualification showed that a module-only evidence value
loses the information needed to choose a grounded repair. The same missing name can
occur in a runtime import, test, platform branch, guarded fallback, or documentation
file. Without file, line, source identity, and collector assessment, a policy can
mistake a Python-version branch for an ordinary package obligation.

V3 keeps the v2 constraint semantics unchanged and adds the structured finding ID
and provenance to both requirement and observation evidence values. The existing
normalizer reads the same typed `name`/`present`, `specifier`/`version`, or equality
fields; extra provenance remains attached to the evidence referenced by the
constraint. No repository map or import-to-distribution guess is added.

This amendment used one already consumed development artifact for read-only
qualification. It made no model request, benchmark execution, source mutation, or
held-out inspection. Generalization still requires a new frozen development batch.
