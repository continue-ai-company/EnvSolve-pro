# EnvSolve-Pro Operation Frontier V5

日期：2026-08-30

## 研究问题

在不限制强 Agent 的命令选择、也不把构建历史直接变成最终部署程序的前提下，如果让它
看到每次环境操作经过验证的真实效果，能否提高部署可靠性？

## 为什么 V4 不适合作为核心算法

Minimal B 为一个 Agent 提供连续 session、持久 shell，以及可反复调用的完整程序干净
重放。V4 进一步把构建命令累计成可编辑程序。完整 Hard6 六个 pair 中，Minimal B 的有效
Official 结果为 5/6，V4 为 4/6。V4 使用 414 对 353 次模型请求、23.47M 对 13.57M token、
26,716 对 17,098 秒，以及 24 对 7 次干净重放。

问题不在于编辑能力不够。V4 容易把 shell 退出状态误当成目标状态确实改变，也容易把构建
环境中的临时路径当成可移植部署方案。它通过了前三个较简单 pair 和 NoneBot2，但 GeoApps
在 120 次请求后失败，scVelo 在 6 次 replay 后仍失败。修正旧构建态审计后 Minimal B 的
GeoApps 最终原样程序通过，scVelo 则两者都失败。PyRollbar 和 LangGraph 的 V4 成功也依赖
多轮 replay 修复。完整结果在成功率和资源两方面都否决了累计可编辑程序作为核心方法。

## 用通俗的话解释 V5

在第一次模型请求前，Harness 先记录公共目标基线。当 Agent 声明“这条命令是为了改变
环境”后，Harness 立刻运行完整公共目标，并告诉它：哪些问题刚刚解决、哪些问题新出现、
哪些问题仍然存在。为了避免反复观测耗尽模型上下文，
模型会看到精确数量、每一部分最多 128 个义务身份，以及明确的截断标记；完整证据保留在
机器轨迹中，需要时 Agent 仍可检查原始目标。Agent 保留同一个 session，继续自由决定
下一步。

Harness 不会把这条命令自动写进部署程序。只有活跃环境工作后，Agent 才编写一份自包含
程序，并在干净环境中重放。重放失败仍回到同一个 session 修复。

## 三层架构

**观测层：** 先记录公共目标基线；每次声明为 `change` 的操作之后，返回命令输出，以及
对完整公共目标状态的诚实有界投影。

**约束层：** 只维护当前可执行验证得到的问题，以及刚解决和新引入的问题。它是证据，
不是包规则。

**操作层：** Agent 自由选择开放 Bash 操作，最后由 Agent 自己综合出可移植的完整程序。

## V5 没有增加什么

V5 不增加包或版本规则、命令过滤、自动回退、checkpoint、跨 case 记忆、控制器分类器或
硬语义否决，也不再增加一个候选 session 或完整程序搜索循环。

## 首次资格实验

第一轮成对比较只使用三个已经消耗的 case：Conan、PyRollbar 和 LangGraph。它们分别
覆盖 V4 的效率正例、严重重放放大负例和混合结果，避免只挑对 V5 有利的样本。每个 pair
都在相同 case、模型、provider、seed、主机 lane、公共目标、evaluator 和宽松安全上限下，
重新运行 Minimal B 与 V5。

Official Pass 是主指标。如果成功率打平，再判断按操作返回的状态差量是否真正改变了诊断
或恢复路径，并报告 request、token、时间、shell 操作、观测截断和重放次数。这三个已
消耗 case 只能验证机制是否值得继续，不能用于估计泛化能力。

## 资格实验结果

两种方法在三个 case 上都达到了 clean replay 目标通过。V5 的三个可裁决 Official 评测
全部通过；Minimal B 的 Conan 和 LangGraph 在原脚本网络诊断后通过，PyRollbar 因旧边界
误伤探索环境、随后两次诊断又被网络删失，Official 结果仍不可裁决。因此这组实验不能估计
成功率差异。

聚合上，V5 将请求从 233 降到 130，token 从 9.11M 降到 5.33M，shell 调用从 240 降到
146，墙钟时间从 9449 秒降到 6827 秒，但 case 间差异很大。PyRollbar 中，经过验证的
`61→0` 路径结束了反复尝试 PATH 和环境的循环；LangGraph 中，frontier 正确跟随 Python
3.11 环境从 47 降到 0，但 Agent 随后继续检查部署完整性，因此比 B 使用更多 token 和
时间；Conan 中，Agent 只在临时 Python 环境里操作，没有把它留给持久观测 shell，所有
frontier 观测都原地不动。

这支持继续验证机制，不支持提前宣称性能提升。固定 Dev batch 前，只做两个通用纠正：已有
安全审计以最终 clean replay 环境为准，而不是以可丢弃的探索环境为准；prompt 明确要求变更
后的 Python 环境必须保持为后续观测的活跃环境。不增加包规则、checkpoint、命令 gate、
跨 case 记忆或自动 planner。
