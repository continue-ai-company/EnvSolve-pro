# EnvSolve-Pro 认证—修复消融实验 v1

日期：2026-08-05

## 研究问题

上一轮仓库不重合的 Minimal B 开发实验得到 Official Pass@1 5/5 对 4/5，但五条
Minimal B 轨迹的第一次干净重放都成功了。因此，这个结果不能证明“重放失败反馈帮助
Agent 完成修复”。本轮将原 treatment 中混合的两个机制拆开：

1. **认证感知的方案构造**：Agent 知道最终程序必须在干净环境中通过一次；
2. **反馈驱动的继续修复**：第一次干净重放失败后，同一个 Agent 可以修改程序并再次重放。

## 冻结实验臂

| 实验臂 | Agent session | 生成阶段的干净重放 | 接受条件 |
| --- | --- | --- | --- |
| A：强 Agent 对照 | 一个连续 session | 无 | episode 结束后评测最终程序 |
| B：单次认证 | 一个连续 session | 恰好一次 | 最终程序必须匹配通过的证书 |
| C：可重试 Minimal B | 一个连续 session | 可重复调用 | 最终程序必须匹配某次通过的证书 |

三臂使用相同模型、推理强度、公共目标、开放终端、持久构建容器、生成时限、episode 后
Official evaluator、仓库完整性策略、精确 revision 源码缓存和进程树超时清理。

B 会看到唯一一次重放的结果，但无法再取得证书。因此，B 对 C 测量的是“能否把失败
反馈转化成一个重新验证过的新程序”，并不单独隔离“是否看见反馈”。

## 机制结果

主指标仍是按仓库配对的 Official Pass@1。以下结果必须分开报告：

- **首轮重放成功**：第一次执行的干净重放通过；
- **修复机会**：C 的第一次重放为 Fail 或 Unknown；
- **修复机制激活**：C 在同一 session 中随后认证了不同程序；
- **修复成功**：激活修复后取得 Official Pass；
- **仅认证效应**：B 与 A 的 Official Pass 差异；
- **可重试效应**：C 与 B 的 Official Pass 差异。

基础设施错误不计为任务失败；相同条件重试前必须冻结 amendment。B 的第二次调用被拒绝
属于 treatment 结果，不属于基础设施错误。

## 决策规则

要支持“反馈驱动的继续修复”，至少需要一条 C 轨迹满足：第一次重放 Fail/Unknown，
同一 Agent 后续重放通过，并最终取得 Official Pass。没有这段轨迹，即使 C-only pass
出现，也不能归因于修复机制。

如果 C 再次全部首轮通过，本轮仍然没有在线迭代修复的证据，不能据此继续加入结构化
状态层。此时应该研究的是 B 与 A 是否不同，以及“一次认证要求”为何改变方案构造。

如果修复激活但 C 不优于 B，应分析反馈是否不可操作、Agent 是否没有修改关键操作，或
干净重放契约是否误拒绝有效方案，不能加入 case-specific 规则。

## 开发筛选实验

在执行前，从上一轮 Minimal B 配对实验后仍未使用的 53 个仓库中选择 8 个。选择只依赖
冻结 salt 与仓库 identity 的哈希，不读取仓库内容、历史结果、包类别或预期难度。

筛选实验共 24 条 episode，每个仓库轮换三臂顺序。全部 episode 完成前禁止修改算法。
这只是开发阶段的机制门，不支持 held-out 或榜单结论。如果机制存活，必须再次冻结后再做
更大的仓库不重合 replication，并继续保护 Official test split。

## 资源报告

Token 或美元成本不作为成功求解的停止阈值。模型 token、命令数、wall time、重放次数和
基础设施重试只作为次指标报告。内存、磁盘和网络只有在三臂能够一致测量时才报告；缺失
这些指标不改变 Official Pass 和机制激活判断。

## 明确排除

本轮不加入结构化状态、compatibility ledger、checkpoint、假设分支、bootstrap 最小化、
跨 case 记忆、evaluator 在线反馈、包管理启发式或 case-specific 策略。
