# EnvSolve-Pro M1 项目进度状态实验收口

日期：2026-09-10

机器可读证据：`experiments/analyses/envsolve_pro_m1_project_progress_closeout_20260910.json`

## 研究问题

M1 检验的是：把项目已经取得的可执行进度整理成一份很小的显式状态（`P`），是否真的优于两种更简单的历史复用方式：

1. `R0`：先重放最近一次成功的部署程序，只有程序真实失败后才启动新的强 Agent 修复。
2. `R1`：继承强 Agent 的完整历史，并且每次都要求它继续改进部署。
3. `P`：先重放；真实失败后，把成功程序、验证条件、已观察到的状态变化和未解决风险交给新 Agent。

实验预先固定了 4 个 consumed/Dev 项目。每个项目运行同 Python 的新环境 `D1`，以及仓库明确支持的相邻 Python 版本 `D2`。三组都使用 `gpt-5.6-sol`、`xhigh`、相同 public goal、Spark 执行环境和 episode 结束后的 Official 验证。终局成功和新增模型用量是共同主要指标。

## 实验结果

| 方案 | 观察到的 Official 结果 | Input tokens | Cached input | Uncached input | Output tokens |
|---|---:|---:|---:|---:|---:|
| `P` | 8 Pass | 3,881,243 | 3,578,240 | 303,003 | 26,059 |
| `R0` | 6 Pass、1 个外部失败、1 个未知 | 3,639,529 | 3,287,168 | 352,361 | 23,136 |
| `R1` | 7 Pass、1 个未知；其中 2 次不能进入主要比较 | 9,355,543 | 8,576,640 | 778,903 | 24,387 |

`P` 的 8 个格子全部 Official Pass，但这不能证明它的成功率高于对照组：`R0` 和 `R1` 所有真正获得算法判定的格子也都通过了；剩余格子是外部下载失败或 qualification 证据无效，不是部署逻辑失败。

`P` 相比 `R1` 节省了 58.5% 的总 input token，但相比 `R0` 多用了 6.6% 的总 input 和 12.6% 的 output。只比较受控的 D2 条件变化，`P` 比 `R0` 多用了 90.2% 的 input。因此，`P` 没有满足预注册的晋级条件：在保持成功的同时，比两个对照都减少新的模型推理。

每次运行的执行、qualification 和重试时间都保留在 position 记录中。由于各 arm 顺序运行，遇到的包缓存、依赖解析、下载和 censor 条件不同，本轮不对总 wall time 作算法因果比较。

## 阶段裁决

**不把显式项目状态提升为 EnvSolve-Pro 核心算法。** 它保留为消融和负结果。当前最强、也最简单的方案仍是 `R0`：干净重放已成功的可执行程序，只有观察到真实程序失败后才调用强 Agent。`R1` 不适合作为默认方案，因为完整历史让 input 达到 `R0` 的 2.57 倍，却没有带来可判定的成功率增益。

M1 到此结束；在阶段评审前不授权 M2，也不修改核心算法。

## 新认识

第一，成功程序可以复用，但它不是稳定不变的环境说明书。`reproject` 的 D1 中，名义上相同的旧程序先在 `P` 和 `R1` 通过，稍后却在 `R0` 因依赖回溯到旧版 Shapely 而失败。R0 的修复成本是真实成本，但由于三组不是同一时刻运行，不能把差异归因为 P 的显式状态。

第二，给强 Agent 更多历史不等于更高效。`R1` 在 preflight 已通过时仍消耗模型推理，最后往往只返回完全相同或语义等价的程序。在本轮实验中，更多记忆没有换来更好的终局结果。

第三，同样 Official Pass 的程序，可能使用不同重试机制、环境工具、依赖约束和安装范围。我们会标记这些完整性与鲁棒性差异，但一切仍以 EnvBench Official 为终局标准；这些标记不能替代榜单成功率。

## 下一阶段评审问题

下一步不应该继续扩大状态结构。更值得直接检验的问题是：在预先固定的真实 Official bad case 上，失败触发的干净重放加新 Agent，能否比最强外部 baseline 更稳定地把失败转成 Official Pass，或者在不降低成功率的前提下减少无效探索。

进入 M2 前还需要决定：是否直接开展这项实验，以及是否把依赖解析和下载漂移作为需要重复执行的实验条件。M1 没有为新增跨候选约束、hash、冻结 contract 或 gate 提供依据。
